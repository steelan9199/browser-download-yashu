# 自进化与维护

> **只在改动本技能时读**。日常下载任务不需要本文件。

## 一、总原则

**文档只做参考，实测才是唯一标准。** 拿到硬证据（可复现报错 / 探针输出 / 真实下载产物 /
官方文档原文）证明某条知识有误，就当场删掉并写入已验证的，**不许拿文档硬扛实测结果**。

> **什么叫硬证据**：**你这次会话里亲自执行了某段命令，并看到了真实输出。**
> 速记：**没跑过 = 推断，不管读过多少行脚本都不算证据。**

四条推论：

1. **知识进出不对称**：进门槛严，出门槛更严。**只留经过验证的当前正确结论。**
2. **文档不是日志**：本技能**不记录"遇到过什么"，只记录"现在应该怎么做"**。
   想查历史去翻 git tag，那里有每一次提交的完整快照。
3. **一个坑只留一条**：同根因的多种表现合并成一条，不按现象分叉条目。
4. **🔢 不在文档里写会过期的数量**：「6 个脚本」「5 个坑」这类数字一变就要全库同步改。
   正确写法是**指向权威清单**，让清单本身成为唯一真相。

   > **⚠️ 例外：作引用锚点的编号不算「过期数量」，必须保留。**
   > `坑 3`、`§三 删错门槛` 这类编号是**跨文档引用的地址**，删掉等于让指针悬空。
   > 判据：**这个数字有人拿它定位东西吗？** 有 ⇒ 保留；没有 ⇒ 删。

**贯穿全文的立场：本技能要能自己长大。** 发现错误就改，别把"要不要请示"当默认动作——
只有不可逆、或会削弱安全网的动作才停下来问（见 §四 授权分级）。判断口径就一条：
**能不能靠 git 回滚 + 门禁能不能拦住**。能 ⇒ 直接改。

## 二、收录判据（五条门槛，全过才准进文档）

**这是本文件的核心。** 目的是防止文档退化成无边界的踩坑流水账——
本技能每次任务都可能撞上一堆报错和临时故障，若来者不拒，`references/` 很快会膨胀到
读不动、检索不到、命中率崩掉。

| # | 门槛 | 判据 | 反例（不准进） |
|---|---|---|---|
| **G0** | **有硬证据**（你亲自跑过，输出在终端里） | 没实跑过的一律不进 | 读几行脚本就下结论、凭记忆断言浏览器行为 |
| **G1** | **不可从脚本/报错直接推断** | 读一遍脚本或报错就能自己查出来的 | "curl 要加 `-L`"（`curl -h` 里写着） |
| **G2** | **实测复现 ≥2 次，或单次代价 ≥3 分钟** | 偶发一次的、复现路径不稳定的 | 单次手滑参数写错、重试一次就好的 |
| **G3** | **静默失败，或失败代价为返工/白跑** | 报错清晰、一次定位到行的不算 | 路径拼错、工具未安装 |
| **G4** | **能写成一条可执行的正确做法** | 只能说"注意这里容易错"而说不出该怎么做 | 纯情绪、纯猜测、纯 TODO |

> **G0 是总闸，其余四条管的是"值不值得写"，G0 管的是"是不是真的"。**

**三条优先收录（即使 G2 边缘也收）**：

- **静默失败类**：不报错、退出码 0、但产物不对（下到防盗链占位图、只下到画面没下到音、下成缩略图）。
- **高耗时类**：卡住、干等、反复重试（无头实例起不来、死磕 cookie、反复调坐标点右键）。
- **本机绑定类**：与本机路径、工具版本、浏览器行为相关的具体事实。换个环境就失效的知识价值低。

**明确不收**（当场丢弃，不要"先记着"）：

- yt-dlp / ffmpeg / PowerShell 官方文档已写明、报错信息已直说的；
- 一次性环境故障（磁盘满、网络抖、临时目录被清）；
- 只在这一个站点/一次任务成立的私货写法，未在其他场景验证过；
- 任何形式的"以后可能用得上"。

**收进哪里（决定体积的关键）**——**每篇上限 10000 字符（见 §九 体量红线），超了就拆，不许调阈值**：

| 内容类型 | 归属 | 理由 |
|---|---|---|
| 公共硬约束 / 红线（所有路线都要遵守，漏读 = 白跑、返工、破坏合规） | **常驻 `SKILL.md`** | 漏读即事故，且人人适用 |
| 某条路线专属的硬约束（如电商取值的防盗链、CDP 的 UA 覆写） | 那一篇（如 `ecommerce-gallery.md`） | 只服务一条路线，常驻层是净浪费 |
| 坑的「现象 → 原因 → 解法」 | `references/troubleshooting.md` | 命中窄、体积大 |
| 某条路线的完整做法与清单 | 对应路线文档 | 按路线分流，不必都读 |
| 改本技能的规则 | `references/自进化与维护.md`（本文件） | 只在改技能时读 |

> 这张表同时也是**拆分依据**：判断标准是**共享性**（是不是所有路线都要用），
> **不是读取频率**。只属于某条路线的内容，即使每次做那条路线都要读，也该留在那条路线的文档里。

## 三、删错门槛

只有**硬证据**才动手删；仅"我觉得可疑"不动手——**误删一条对的知识比留着错知识更难发现**
（错知识有痕迹，对的知识被删了就像它从来没存在过）。

**删之前先自问：「我要删的这条，我自己验证过吗？」** 如果当初删它靠的是"读脚本推断"而不是实跑，
那它可能根本不该删。**发现疑似错误时，第一反应是跑一次验证，不是改文档。**

删的时候**删干净**：不并存、不标注、不归档，**连"曾记录 X、已推翻"这类痕迹都不留**。
想查历史去翻 git tag。

**连带禁止「负向声明」**：文档里不许出现「已废弃的旧口径」「勿再使用」「本节曾要求…现已推翻」
这类写法——它把已删掉的旧知识**原样抄回上下文**，读的人（包括 AI）等于把错误知识又收了一遍，
比不写更坏。**文档只写当前正确规则。**

自检：`node scripts/skill_audit.js` 会扫全库这类写法并列出命中行号。

## 三·五、引用必须「序号 + 标题」成对写

**章节引用一律写成 `§序号 标题`，不许只写 `§序号`。**
正确：`§九 体量红线`、`ecommerce-gallery.md §三 下载`。
错误：`见 §九`、`详见 §2`。
**序号**定位快，**标题是唯一稳定锚点**——本技能按「共享性」持续拆章重排，序号必然漂；
只写序号会变成悬空指针，**且断得毫无痕迹**，门禁也兜不住（它只校验文件名）。

新增/改名/重排章节时，顺手改「序号 + 标题」这一对（章节标题也属 §三 删错门槛 的「删干净」范围）。

## 四、授权分级

**默认自进化：取证充分即可直接改，不必请示。** 目的是让技能能自己长知识，
而不是每次都要人点头——卡住自进化的请示成本，比改错的成本更高。

| 改动类型 | 授权 |
|---|---|
| 事实订正 / 删除已证伪的句子 / 补实测结论 / 修文档笔误 | **直接改** |
| **新增知识**（过了 §二 收录判据 的五道门槛）/ 改写表述 / 调结构与顺序 / 补断链与去重 | **直接改** |
| **跨多个文件的联动改动**（如同一结论在 3 份文档里都写错了） | **直接改**，改完在回复里逐个列出 |
| 动 `SKILL.md` 硬约束 / 红线 / 体量红线 | **直接改**，但回复里必须**显式说明改了什么、依据是什么** |
| 删脚本 / 删 git tag / 改推送目标（origin）/ 让门禁红灯被绕过 | **必须报备** |

只有最后一类才需要停下来问——它们都不可逆或会削弱安全网。
判断口径：**能不能靠 git 回滚 + 门禁能不能拦住**。能 ⇒ 直接改；不能 ⇒ 先问。

## 五、版本号规则

frontmatter 的 `version` 用语义化版本，**每次修改必须递增**：

| 递增位 | 适用场景 |
|---|---|
| patch（第三位） | 订正错误 |
| minor（第二位） | 新增知识 / 新增章节 / 新增自进化机制 |
| major（第一位） | 结构性重写或红线变更 |

判定：比对新旧版本号，**第一个发生变化的数字位**即递增位；一次改动跨多档按最高档算。

## 六、位次决定推不推

- patch ⇒ **只落盘、不碰 git**，攒到下次 minor/major 一并提交；
- minor / major ⇒ 视为**已获推送授权**，改完即提交推送并打 tag，**不再问**。

## 七、push / tag / 回滚纪律

1. 一律用 `node push.js "<说明>"`（等价于 `git add -A` → commit → push → tag），
   **禁止裸跑** `git add/commit/push`（裸跑靠 cwd 向上找仓库，可能命中别人的仓库）。
2. `push.js` 内置三道闸：① 仓库根 realpath 校验（`C:/Users/...` 与 `D:/CToD/...` 是同一目录的
   两个视图，**必须归一后比对**）；② `origin` 必须等于本技能仓库；③ 提交前跑本文件的复测命令，
   不过就拒推。
3. **每次 minor/major 推送必带 tag**（`v<版本>-<时间戳>`）。tag 是回滚的唯一落点：
   - 回滚看历史：`git -C <技能目录> tag`；
   - 回滚代码：`git -C <技能目录> checkout <tag> -- .`（只回滚文件，保留 git 目录）；
   - 回滚整个版本：`git -C <技能目录> reset --hard <tag>`。
4. 暂存用 `add -A`，故 **`.gitignore` 是唯一过滤网** ⇒ 新增临时目录/产物类型必须同步补进它。
5. **不记变更历史**：只维护版本号，不写 CHANGELOG（git 历史就是 CHANGELOG）。

> **⚠ 改 `push.js` 前必读：`spawnSync` 在本机一律返回 `EBUSY`，只能用异步 API。**
>
> **现象**（2026-10-07 实测）：`spawnSync` 对 `git` / `cmd` / `pwsh` / 甚至
> **一个根本不存在的可执行文件**全部返回 `EBUSY`；而同一进程内
> `await execFile("git", ["--version"])` **正常返回**。
>
> **⚠ 归因：只锁定在 `spawnSync` 这一个 API 上。不要归给环境、node 或 git。**
> 下面每条都实测否掉了，别再往这些方向猜：
>
> | 曾怀疑 | 实测结果 |
> |---|---|
> | 是 git 的问题 | ✗ 不存在的可执行文件也报同样 EBUSY |
> | 是 PATH / `shell:true` / cwd / 绝对路径问题 | ✗ 四种都试过，一律无效 |
> | 是 WorkBuddy 沙箱限制 | ✗ 关沙箱（`dangerouslyDisableSandbox=true`）与独立 PowerShell 进程里同样失败 |
> | 是某个 node 构建的 bug | ✗ v22.13.1 与 v22.22.2 两个独立二进制表现完全一致 |
> | 是 Windows 限制了 git/pwsh/node | ✗ 在 pwsh 里直接敲 `git` 完全正常 |
>
> **⚠ 容易误判的地方**：在 pwsh 里敲 `git` 走的是「PowerShell → git」，**不经过 node**，
> 所以正常；而这里是「node → spawnSync → git」，卡在 node 自己的同步 API 上。
> 两者现象不同，不要混为一谈。
>
> **结论**：本机 git / pwsh / node 全部正常，**只有 `spawnSync` 这一个同步入口不可用**。
> 因此 `push.js` 的 git 调用必须走异步 `execFile`，**不要改回 `spawnSync`**。

## 八、复测（改完必跑，不跑等于没改）

```powershell
node scripts/skill_audit.js              # 只跑门禁，不提交不推送
node scripts/skill_audit.js --top        # 附体量 TOP 8 与断链明细
node scripts/skill_audit.js --json       # 机器可读
node scripts/skill_audit.js --save       # 记一条历史，作为下次对比基准
node push.js --check                     # 只跑门禁（不碰 git，git 不可用时也能用）
```

门禁检查四件事，任一不过退出码 1：

1. **引用断链**——`SKILL.md` 与 `references/` 里提到的文件是否真实存在；
2. **负向声明**——全库有无「已废弃 / 勿再使用 / 已推翻 / 曾要求」类痕迹；
3. **工具路径一致性**——全库出现的工具路径必须命中权威前缀表（对应 `SKILL.md` 环境前提里的固定事实）。
   **这是本技能最贵的一类错误**：ffmpeg / yt-dlp / node / Edge 的路径散落在文档与各脚本里，
   一处改了别处没改 ⇒ 静默用错工具或直接跑不起来，而报错信息常常指向别处。
   扫全目录（含技能根目录），`.ps1` / `.mjs` / `.js` 也要扫。
4. **体量红线**——所有 markdown 文档（`SKILL.md` 与每篇 `references/*.md`）统一 **≤10000 字符**，超了必须拆分。

> 门禁**查不出语义矛盾**（同一件事在两处说法冲突、章节编号错位、
> 文档内嵌的命令副本与脚本本体不同步）。这类问题靠人/AI 通读比对，
> 门禁只兜住结构层。

## 九、体量红线

**唯一红线是字符数：本技能所有 markdown 文档（`SKILL.md` 与每篇 `references/*.md`）都 ≤ 10000 字符**，超了必须拆分，**不上调阈值**。

这里的"成本"不是文件大小，而是**被读进上下文的次数**：常驻层每轮对话重发一次，
`references/` 命中才读一次。**一段内容移出常驻层，付费次数就从 N 变成 1。**

- **拆分依据是共享性**——判断标准只有一条：**这条内容是不是所有路线/任务都要用？**
  - **公共部分** ⇒ 留 `SKILL.md`（常驻层，每轮对话重发，必须人人适用）。
  - **非公共部分**（只属于某条路线）⇒ 下沉到对应文档，`SKILL.md` 只留一行指针。
  - **判断不了就问两个问题**：①去掉它会不会有人踩坑？②漏读它会不会**静默返工**
    （命令能跑、产物不对，却没有任何报错提示）？
    - 会踩坑 **且** 漏读只是多花时间 ⇒ 公共，留 `SKILL.md`。
    - 不公共，但漏读会**静默返工** ⇒ **例外**，可留常驻层，但必须写清「为什么留」。
    - 不公共，漏读只多花时间 ⇒ 下沉到对应文档，`SKILL.md` 留一行指针。
  - ⚠️ **不要拿「读取频率」当拆分依据**。高频 ≠ 公共——「高频但只服务一条路线」的
    内容塞进常驻层，等于让所有路线为它付上下文成本。
- **⚠️ 单篇超 8000 字符的 references 必须在 `SKILL.md` 路由表标 ⚠️**，
  提示"先 Grep 局部读"。`node scripts/skill_audit.js --top` 会算出并列出命中文件。
  **路由表里不要写"体量"数字列**——那是最易过期的一类数字（见 §一 总原则 的第 4 条），标 ⚠️ 就够。
- 当前余量**不写在这里**，跑 `node scripts/skill_audit.js` 现看。

## 十、备份：用 git，不用复制文件夹

**git 就是本技能唯一的备份。** 它同时提供完整历史、任意时点回滚、按版本整体回退，
`cp -r` 三样都做不到。

改动前的标准动作，**不要拷文件**：

```powershell
git -C <技能目录> status --porcelain        # 确认工作区状态，知道自己在改什么
git -C <技能目录> tag --sort=-creatordate    # 确认有 tag 作回滚落点
```

- patch 级改动：工作区本身就是"改动前状态"，**不需要任何额外备份**。
- minor/major：改完走 §七 push / tag / 回滚纪律 的 `node push.js`，它会自动 commit + push + 打 tag，
  **tag 就是回滚落点**。
- 回滚：`git checkout <tag> -- .` 回滚文件，或 `git reset --hard <tag>` 回滚整版。

**只有一种情况需要临时拷贝**：没有 tag 兜底的大重构前。此时拷一份，**改完提交后立刻删掉**——
它是临时垫片，不是历史。长期堆积 `_backup/` 与本文件 §一 总原则 的第 2 条「文档不是日志」相悖：
git tag 已经存了每一次快照，再堆全量副本只是白占空间、让人误以为那是唯一退路。
